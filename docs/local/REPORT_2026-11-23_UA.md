scripts/harness2-local: локальна команда status/demo/test, що використовує .venv незалежно від поточного каталогу й системного Python. Посилання: /home/user/.local/bin/harness2-local.

docs/local/requirements-X99MG.txt: зафіксовані фактично встановлені версії залежностей.

## Запуск

На X99MG:
```bash
/home/user/.local/bin/harness2-local status
/home/user/.local/bin/harness2-local demo --k 2
/home/user/.local/bin/harness2-local test
```
Детальні результати демонстрації: /home/user/src/harness2/runs/local-demo/.

Для перевстановлення на сумісному Linux:
```bash
uv venv --python 3.12 .venv
uv pip install --python .venv/bin/python -e '.[render]'
```
Запускати з каталогу checkout; локальний commit містить виправлення та launcher.

## Межі доказів та наступний крок

Перевірено core/demo та парсер Codex. Демонстрація використовує детерміновані локальні редактори; успіх не доводить покращення реального R&D-агента.
Зовнішні модельні API не викликались, платні запуски не проводились, ключі не налаштовувались. Живий Codex executor, bridge, GCloud і benchmark datasets не перевірялись. Upstream executor обходить approvals/sandbox; для модельних проб потрібне окреме тестове середовище.

Для RF/FPGA потрібен окремий доменний адаптер: вибрати одну перевірювану задачу, визначити незмінні обмеження, підготувати вихідні дані та незалежний критерій результату, потім виконати обмежену пробу з бюджетом. Це ще не реалізовано.

## Відкат

Зміни зберігаються окремою локальною Git-гілкою local/x99mg-integration. Перемикання на main повертає upstream-файли; перед цим перевірити git status. .venv і runs залишаються локальними. Launcher видаляти лише після перевірки, що це посилання на цей checkout. Публікації в upstream не було.
